ENGINEERING DECISIONS

The interesting
part of the work.

The constraints, the trade-offs,
and how I approached them.

01

The JWT can expire mid-session while the user is browsing.

+
THE DECISION

An OkHttp Authenticator catches 401s, silently refreshes the token and retries the original request — transparent to the UI layer. A play only counts after 15 continuous seconds, to avoid counting brief starts as full plays.

02

Android can kill the process and stop playback.

+
THE DECISION

A Foreground Service and MediaSession support playback and media controls while the app is backgrounded. START_STICKY provides a restart strategy, subject to Android lifecycle restrictions and user-initiated stopping.

03

Scoped Storage changed how files are written on Android 10+.

+
THE DECISION

Branch by SDK version — Android 10+ uses the MediaStore API (ContentResolver), 9- uses the file system directly. Either way, metadata lands in Room DB.

What I take from this project

  • Playback needs lifecycle-aware state and recovery, not only an audio player component.
  • A repository boundary helps UI flows share data without sharing every implementation detail.

Scope & limitations

  • Foreground services support background playback but do not guarantee the app can never be stopped.
  • My scope covered the artist module, detail/search/share/profile flows, UI/UX and database co-design.
